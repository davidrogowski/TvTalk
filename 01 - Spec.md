# TvTalk — Spec

## What this is

A personal soundboard web app: a virtual button that plays a random audio clip (a quote from a TV show or movie) and shows the text on screen. Supports multiple shows via a picker, with a "Random (all shows)" option. Clips are scraped from 101soundboards.com.

## Goals & non-goals

**Goals**
- Browser-only frontend, no build step, runs on a Mac by double-clicking or via a one-liner local server.
- Adding a new show is a 5-command workflow.
- Curation (assigning character names to clips) is a single text file I edit by hand, and my edits survive re-runs of the scraper.
- Docs and code coexist in the same folder, browsable from the parent Obsidian vault.

**Non-goals**
- No accounts, no sync, no hosting. Personal use only. *(Since superseded: the site is now hosted at tvtalk.fun — see [[05 - Deployment]]; verify scripts exist under `scripts/`; mobile is supported.)*
- No parallel scraping, no proxies, no detection-evasion. The 101soundboards site gets one polite request at a time.
- No audio editing — clips are used as-is from the source board.

## Components

### `scripts/shows.yaml`

The single source of truth for which shows exist, where to scrape them from, and how to theme the UI for each. Required fields are `id`, `name`, `board_url`, `theme`. Several optional per-show fields exist for boards that need cleanup or special handling.

```yaml
shows:
  - id: the-boys                   # slug, used as folder name in audio/ and id in shows.js
    name: "The Boys"
    board_url: "https://www.101soundboards.com/boards/1375005-the-boys-2019"
    status: pending                # pending | scraped | wip
    theme:
      primary: "#c41e3a"           # button color, primary text accents
      accent:  "#d4af37"           # secondary accent (gold)
      bg:      "#0a0000"           # darkest background color

    # Optional fields below — add only if the board needs them:
    board_url_2: "https://..."             # merge a second board into the same show (deduped by MP3 URL)
    text_style: "title"                    # "caption" (default, wrap in quotes) or "title" (no quotes — for user-uploaded clip titles)
    case_style: "fix_all_caps"             # convert ALL-CAPS legacy captioning to sentence case; default "preserve"
    exclude_prefix: "CAPTIONING MADE BY"   # drop clips whose transcripts start with this (case-insensitive)
```

### `scripts/scrape_soundboard.py`

Behavior:

- **Mode 1 — config-driven (default):** `python3 scripts/scrape_soundboard.py` scrapes every show in `shows.yaml` whose `status: pending` OR whose `audio/<id>/` folder is missing files. `--show <id>` restricts to one show. `--all` re-scrapes even already-scraped shows.
- **Mode 2 — ad-hoc:** `python3 scripts/scrape_soundboard.py <board_url> [out_dir]` for one-off boards. Output goes to `out_dir` or `soundboard_output/`. Per-show YAML fields don't apply in ad-hoc mode.
- **Per-show folders:** in config mode, audio goes to `audio/<show-id>/`.
- **Data source:** the 101soundboards JSON API at `/api/v1/boards/{board_id}?limit=2000` (discovered by inspecting their Vite bundle). Returns all clips in one response, no pagination handling needed. The old HTML regex approach was abandoned because the site renders only the first 50 clips inline and loads the rest via JS.
- **SSL:** uses `certifi`'s CA bundle explicitly via a custom `ssl.SSLContext`. Homebrew Python on macOS often ships with an empty system CA bundle which breaks `urllib`'s default verification.
- **Filters:** `--min-length` (default 1 word), `--max-length` (default 25 words). For long-monologue boards (Narcos, Succession, Ozark, Atlanta, etc.) bump `--max-length 50` or higher.
- **Universal transcript cleanup:** the JSON API returns transcripts with hashtag tag-clouds appended (`"Quote text #tag1 #tag2"`). The scraper strips everything from the first `#` onward.
- **Multi-board merging:** if a show entry has both `board_url` and `board_url_2`, both boards are fetched and their clips deduped by MP3 URL into the same output folder.
- **Per-show transcript transformations:**
    - `case_style: "fix_all_caps"` — for any clip whose transcript is entirely uppercase, convert to sentence case (preserves standalone "I", capitalizes after `.?!`).
    - `exclude_prefix: "..."` — drop any clip whose transcript starts with the given prefix (case-insensitive). Used for filtering closed-caption disclaimers (e.g. `"CAPTIONING MADE POSSIBLE BY..."`) and stage-direction-only clips (e.g. prefix `"("` for `"(DOOR OPENS)"`).
- **Auto-trim for poisoned legacy boards:** 101soundboards serves a 1-second notification-ding-poisoned MP3 to non-browser User-Agents on community-uploaded boards. The scraper detects these from the URL (board ID < 1,000,000) and trims 1.0s off the front of every newly-downloaded MP3 using `ffmpeg -ss 1.0 -c copy` (stream copy, no re-encode, frame-accurate enough for MP3). Already-downloaded files are skipped to avoid double-trimming on re-scrape.
- **Polite throttling:** 1.5s sleep between downloads. Resumable (re-running skips already-downloaded files via existence check on the destination path).
- **Curation round-trip:** `transcripts.txt` format is:
  ```
  001_oi_cunt.mp3
    "Oi, cunt."
    CHARACTER: Billy Butcher

  002_diabolical.mp3
    "Diabolical."
    CHARACTER:
  ```
  On re-run, the scraper parses any existing `transcripts.txt` first, extracts the `CHARACTER:` line for each filename, and uses those values when writing the new `quotes.js`. Transcript-text edits are NOT preserved across re-scrapes — only `CHARACTER:` lines round-trip.
- **Summary at end:** prints `Downloaded: N, Skipped (already present): N, Skipped (length filter): N, Total kept: N` (plus `Trimmed N` if auto-trim ran).

### `scripts/build_shows.py`

Walks `audio/*/quotes.js`, parses each one, joins with metadata from `shows.yaml`, writes `shows.js` at the project root:

```js
// Auto-generated by build_shows.py. Do not edit by hand.
const shows = [
  {
    id: "the-boys",
    name: "The Boys",
    theme: { primary: "#c41e3a", accent: "#d4af37", bg: "#0a0000" },
    text_style: "caption",   // "caption" (default — wrapped in quotes in UI) or "title" (no quotes)
    quotes: [
      { text: "Oi, cunt.", character: "Billy Butcher", audioUrl: "audio/the-boys/001_oi_cunt.mp3" },
      ...
    ],
  },
  ...
];
```

`audioUrl` is always a project-root-relative path so `index.html` can load it from `file://` or a local server without change. `text_style` is passed through from `shows.yaml` (default `"caption"`) so the UI can decide whether to wrap each clip's text in quote marks.

### `index.html`

Extends the existing single-show HTML. Changes:

- Loads `shows.js` via `<script src="shows.js"></script>`. README documents `python3 -m http.server` as a fallback when Chrome blocks the local script.
- **Show picker** in the header: `<select>` populated from `shows`, sorted alphabetically by name. First option is `🎲 Random (all shows)` (default, value `__random__`, pinned to top regardless of sort). *(Since superseded: the picker is now a searchable combobox with type-to-filter, grouped into TV Shows / Movies.)*
- **Theme swapping** via CSS variables. The page sets `--primary`, `--accent`, `--bg` on `:root`; every colored element (button, h1 text-shadow, accents, body gradient) references these. On show-change, JS updates the variables to the selected show's theme. The default `__random__` selection uses the dark/gritty Boys-style theme defined in CSS as fallback values.
- **Random behavior:**
  - `__random__`: flatten `shows[*].quotes` into one pool; pick uniformly; never repeat the immediately previous quote (track `lastKey = ${showId}::${index}`). With the current 99 titles / ~9,055 quotes, the pool is dominated by larger boards (Family Guy alone is 558).
  - specific show: pick from `shows[i].quotes`; never repeat immediately previous quote within that show.
- **Text rendering:** `showQuote()` looks up the source show by `item.showId`. If the show's `text_style` is `"title"`, the transcript is rendered as-is (no surrounding quote marks); for `"caption"` (default), it's rendered wrapped in `"..."`. This distinction matters because some community boards use clip *titles* like `"A leap of faith"` instead of actual subtitled dialogue.
- **Title** changes to the show name (or `"TV TALK"` for Random).
- **Button styling** has evolved from the original spec into a "Staples Easy Button" look: large round dome (240px, 200px on mobile) with a bright top highlight, dark bottom, and a "base stub" drop-shadow so it reads as a physical button. Clicking depresses it (`translateY`). While audio plays, a subtle theme-colored glow ring pulses *behind* the button (`.button::after`) rather than the whole button pulsing.
- **Per-show themes** are matched to each show's cover-art hue (e.g. Breaking Bad = hazmat yellow + chemical green). The subtitle and footer text from the original design were removed.
- **Mobile:** a `<meta name="viewport">` tag plus a `max-width: 600px` media query shrink the button, picker, and quote fonts for phones.

### Obsidian docs

**`00 - Project Overview.md`** — hub. One-paragraph description, "Where things live" table (mirrors DiscoMode's style), Dataview query listing active shows, Quick Add snippet showing the scrape command.

**`03 - Workflow.md`** — step-by-step for adding a new show:
1. Find a 101soundboards board URL.
2. Add an entry to `scripts/shows.yaml` (id, name, url, theme).
3. Run `python3 scripts/scrape_soundboard.py --show <id>`.
4. Open `audio/<id>/transcripts.txt`, fill in `CHARACTER:` lines for the keepers.
5. Re-run the scraper — `quotes.js` regenerates with your character names.
6. Run `python3 scripts/build_shows.py` to regenerate `shows.js`.
7. Create `Shows/<Show Name>.md` from `_Show Template.md`.
8. Open `index.html` (or `python3 -m http.server` for Chrome).

**`04 - Troubleshooting.md`** — Chrome blocks file://; audio doesn't play (autoplay policy needs user gesture, which a button click satisfies); scraper finds 0 clips (101soundboards changed markup — regex needs adjustment); transcript edits lost (the file was overwritten because you ran the scraper from the wrong dir).

## Acceptance criteria

All five are met as of 2026-05-27 (the catalog has since grown to 99 titles and ~9,055 quotes).

1. `python3 scripts/scrape_soundboard.py --show <id>` scrapes the named show from `shows.yaml`, saves MP3s to `audio/<id>/`, writes `transcripts.txt` and `quotes.js`. Auto-trims poisoned legacy boards.
2. Editing `CHARACTER:` lines in `transcripts.txt` and re-running the scraper updates `quotes.js` without re-downloading.
3. `python3 scripts/build_shows.py` produces a `shows.js` at root listing every show.
4. `index.html` opens, shows a picker with "Random (all shows)" as default, plays random clips, reskins on show change.
5. The Obsidian docs open from the parent vault; wikilinks resolve.

## Out of scope (explicitly)

- Tests. Personal project; manual verification is fine. *(Since superseded: Playwright/pytest verify scripts now exist under `scripts/`.)*
- Mobile-specific styling. Desktop browser only. *(Since superseded: the UI is now mobile-responsive.)*
- Bypassing 101soundboards' anti-scraping detection at the source. We download what they serve to non-browser UAs (which includes the ding) and trim it after the fact. Reverse-engineering their auth/session flow to get the clean stream wasn't worth the effort for a personal project.
- Preserving transcript text edits across re-scrapes. Only `CHARACTER:` lines round-trip.
- Show-weighted random in "All shows" mode. The pool is currently dominated by larger boards but the user's stance has been "it builds over time."
